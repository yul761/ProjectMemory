# StateCore v1 开发路径:夯实 → 契约冻结 → 真实数据反哺

> 记于 2026-06-22 ｜ 本文是 `StateCore-开源核夯实-冻结计划(S1–S6)` 的执行路径修订版。
> 取代原计划中"行为冻结 + 真实数据推迟到冻结后"的设定。

## 背景与战略澄清

托管版初期**只服务作者自己的产品**——作者既是唯一的数据生产者,也是唯一的消费者。
战略闭环是:**自用产品 → 跑出真实数据 → 反哺更新 StateCore 核心算法**。

这与原冻结计划存在一个张力:原计划写"真实数据验证推迟到冻结后",且 S6 要做
"`/v1` 契约**与行为**冻结"。"行为冻结"会挡住用真实数据改进算法的目标。

**破解办法 —— 把"冻结"拆成两层:**

1. **契约冻结(API 形状 / 语义 / 错误模型)** —— W2 已完成,保持。作者的产品需要一个稳定的
   `/v1` 集成面。
2. **算法冻结(digest / drift 的内部质量与输出)** —— **不冻**。digest/drift 内部逻辑本就不是
   `/v1` 契约的一部分;用真实数据把它改得更好,只要不破契约,就是合法的 minor/patch。

结论:**S1–S5 全做(纯加固,与"反哺核心"目标无冲突);S6 重写为"契约冻结 + 算法留活"。**

## 决策:接产品前先把 S1–S5 全做完

节奏上选择"S1–S5 全做完再接产品",而非"先接产品边用边补"。
理由:核心最稳后再喂真实数据,避免早期裸奔;且 S1 建好的测试网是后续敢动算法的前提。

## 开发路径

### 第一段:核心夯实(S1–S5,接产品之前全做完,按原计划顺序 S1 > S2 > S5 ≈ S4 ≈ S3)

| 阶段 | 内容 | 为什么在接产品前做 |
|---|---|---|
| **S1** 漂移鲁棒性 ★ | digest 控制逻辑上 property/fuzz 测试(protected-state merge、novelty 阈值、一致性检查、CJK 守卫)+ 合成对抗 fixture(矛盾轰炸、目标横跳、噪声、文档 churn、多语言混合)+ 修问题 | 将来敢用真实数据动算法的**安全网** |
| **S2** 无状态化 / 多实例安全 | 去进程内状态;**去掉进程内限流**(归托管网关);确认 worker `digest-lock` 并发正确;api/worker 可多副本 | 托管扩容不必重开核心 |
| **S3** 检索规模化 + 性能 | pgvector **HNSW 索引**;压低 retrieve/digest p95(基线 ~4.3s / ~12s) | 内部改动,不破契约,趁冻结前做 |
| **S4** 数据生命周期 | 真正执行 `expiresAt` 清扫 / 保留 / GC(events + embeddings) | 避免长跑膨胀 |
| **S5** `/v1` 入口加固 | 请求体大小上限 + 输入校验(W2 遗留的 ValidationPipe follow-up) | 畸形 / 超大输入也稳 |

### 第二段:S6 重写 —— 契约冻结,算法留活

- 打 **v1.0.0**,冻结的是 **`/v1` 契约(形状 / 语义 / 错误模型)**。
- **不冻结** digest/drift 的算法内部质量与输出(本就不属于 `/v1` 契约)。
- 冷启动验证 + 补一个最小 worked example。
- CHANGELOG + 稳定性政策,写明:
  - `/v1` 契约冻结、additive-only、仅 patch 级修复(bug / 安全)。
  - **唯一保留改动面 = 真实数据驱动的核心算法改进**(对 `/v1` 非破坏性,走 minor/patch)。
    —— 比原计划的"仅漂移正确性 patch"更宽。

### 第三段:接产品 → 真实数据闭环

- 作者的产品接上稳定的 `/v1`,开始产生真实数据。
- 真实数据 → 更新 digest/drift 算法 → 用 S1 建好的测试网兜底 → 发 minor/patch,不破契约。
- 因为契约已冻,产品集成面不受算法演进影响。

## 执行方式

每个 S 都走既有流程:
brainstorm(定范围 / 方法)→ spec → writing-plans → subagent 执行
(每任务双 review + final 全分支 review)→ 合并 + push。

**下一步:从 S1 开始**,单独 brainstorm 其范围与方法。

## 与原计划的差异(一句话)

原计划:S1–S5 加固 + S6 行为冻结 + 真实数据推迟到冻结后。
本路径:S1–S5 加固 + **S6 只冻契约不冻算法** + 真实数据从"冻结后偶发 patch 来源"
升级为"**持续反哺核心的主循环**"。
