# Changelog

All notable changes to this project are documented in this file.

The format loosely follows Keep a Changelog and Semantic Versioning.

This file is the product-level view, one entry per release tag. Per-package
detail is generated by Changesets and lives in `apps/*/CHANGELOG.md` and
`packages/*/CHANGELOG.md`; entries here link there rather than repeat it.

**Three version numbers describe this repository and they do not track each
other.** A release tag (`v1.5.1`) says what shipped and when, and is what this
file is organised by. Package versions (`packages/*/package.json`) say which
build of a package is installed. The frozen contract's own `info.version`, in the
generated OpenAPI document, says how current a `/v1` spec is — it is the number a
consumer cares about, and it moves only on additive changes to the public
surface. `docs/api.md` owns the rule.

## [Unreleased]

## [1.6.1] - 2026-08-14

### Fixed
- The built packages start outside the Docker image. All four pointed `main` at
  `src/index.ts`, which Node cannot execute, and the image worked only because a
  Dockerfile stage rewrote them to `dist` before the runtime started — so the
  image was the one place a built app could be started, and any other consumer of
  the same build died on `SyntaxError: Unexpected token '{'`. That is what
  Integration Smoke had been failing on, behind the pgvector failure that hid it.
  The packages now ship pointing at `dist` and the rewrite stage is gone.
  Source-mode consumers are unaffected: `types` still resolves to source through
  the node_modules symlink, Vitest aliases the names back to source through
  `vitest.shared.ts`, and `tsx` reads the paths in `tsconfig.dev.json`.

## [1.6.0] - 2026-08-14

The first release since `1.1.0` whose theme is the promise rather than the
engine: everything served under the compatibility prefix is now either frozen or
explained, and a test enforces that instead of a documented request. Contract
`info.version` 1.3.0 → 1.5.0 across the two rounds.

### Added
- The three audit readers join the frozen `/v1` contract:
  `GET /v1/memory/facts/:factId/provenance`,
  `GET /v1/memory/digests/:digestId/selection`, and `GET /v1/facet-pack`. All
  three were dual-mounted at `/v1` and absent from `PublicV1Contracts`, so the
  snapshot guard never saw them — in the endpoints that exist to answer "why do
  you believe this, and what did you discard". An integration test now parses
  each live response with its frozen schema, which the other frozen readers get
  from `parseOutput` and these three did not. Contract `info.version` 1.4.0 →
  1.5.0; the surface goes from 18 operations across 16 paths to 21 across 19.
- `POST /v1/memory/notes`, `GET /v1/memory/relationship-context/:scopeId` and
  `DELETE /v1/scopes/:id` join the frozen contract on the same grounds, having
  run under the prefix unguarded for months. Contract `info.version` 1.3.0 →
  1.4.0.
- A guard checks the frozen registry against the routes Nest actually serves, in
  both directions. `PublicV1Contracts` drives the snapshot test, the OpenAPI
  document and the docs table, and all three see only what it declares — so a
  handler dual-mounted at `/v1` without a registry entry was invisible to every
  check, which is how the same drift reached two releases running. A registry
  entry with no route behind it is the mirrored fault and is caught too.

### Fixed
- Scope deletion cascades through the database constraint rather than the
  handler.
- The OpenAPI success code was derived from "is this a GET" and documented
  `DELETE` as 201.
- CI ran no checks. It now provisions the database its migrations and tests need,
  generates the Prisma client, and the tests it runs pass.
- The smoke workflows run a Postgres that carries pgvector. Integration Smoke had
  been failing since 2026-06-20 on `CREATE EXTENSION vector` under stock
  `postgres:16`, and triggered only on `pull_request` — which this repository
  does not use — so it never ran again and the README badge reported that result
  for two months. It now also runs on push to main. Runtime Readiness and Runtime
  Smoke shared the image; both report success on a schedule only because every
  step is gated on a `MODEL_API_KEY` secret that is not configured, so neither is
  currently a signal.

### Docs
- `docs/api.md` records why "serving a path under `/v1`" and "freezing it" came
  apart twice, and why "leave it free to evolve while the design is young"
  expires without anyone noticing.
- The deploy runbook makes the `-f compose.deploy.yml` override impossible to
  omit — leaving it off silently unbinds core's port and returns 502 through the
  gateway, which is how production broke for four hours on 2026-08-09.

## [1.5.1] - 2026-08-08

Contract versioning. The generated OpenAPI document had declared

A number that never moves carries no information — and reads as unmaintained now

## [1.5.0] - 2026-08-08

The benchmark-driven release: an equal-context-budget LongMemEval comparison
against mem0 OSS both produced a publishable result and exposed three defects in
the fact layer that only show up at corpus scale.

### Added
- `POST /v1/memory/retrieve` accepts an optional `maxChars` context budget and
  reports what it refused in a new top-level `budget` field. The "a few large
  items or many small ones" tradeoff decides what a caller gets at a tight
  budget, and was a decision only the engine could make with no way to hear
  about it — callers had reimplemented it themselves. Items are included whole
  or skipped; facts take at most 40% so raw evidence always has room; every
  refusal carries a reason and a score. Additive and optional: a request without
  `maxChars` is byte-identical to before.
- `GET /v1/facet-pack` answers per scope, and reports which layer decided the
  ontology — the scope's `template`, an `account` override, or the
  `deployment-default`.

### Fixed
- A fact is bounded at 500 characters at every write path. Three paths promoted
  `event.content` verbatim, which is statement-sized for a chat message and not
  for a session or a document: 87% of registry entries measured over 1000 tokens
  against genuine extracted facts of 11–27. The fact layer had become a second
  copy of the corpus, crowding out extraction's own output in every
  budget-constrained consumer.
- Stage 2 runs one pass per prompt-sized chunk over the whole corpus. It had
  clipped its candidate section at 60k characters and dropped the rest, so on
  LongMemEval roughly 12% of the corpus reached extraction. Bulk `ingest:docs`
  hit the same wall.
- A degraded stage-2 pass keeps the facts it extracted. Chunking makes a
  consistency trip likely between consecutive chunks, and every degraded return
  discarded `profileFacts` — observed live as a digest that ran 344 seconds,
  reported success, and wrote nothing.
- Backfilled history no longer produces an empty digest. `occurredAt` sets an
  event's `createdAt`, and the digest's lookback filtered on that same column, so
  importing two years of history put every event outside a 14-day window: the
  digest selected nothing and reported success. `MemoryEvent.ingestedAt` is now
  stamped on write and never moved, and a lookback of zero means unbounded rather
  than "select nothing".

### Docs
- `docs/longmemeval.md` publishes the 2026-08-08 run: 194 questions at equal
  context budget, with the earlier two runs withdrawn and their faults recorded
  rather than deleted.

## [1.4.0] - 2026-08-05

Every domain gets the facets its classifier vocabulary routes into. Scope
templates and facet packs were two extensibility mechanisms at two granularities
and only `personal` lined up: `health` classified events as `medical_fact`,
`learning` as `knowledge_claim`, `project` as `decision`, and the account-level
pack routed from none of them — so for three of the four templates, including
the default, stage-1 classification produced labels that landed nowhere. A
scope's pack now resolves from its template, and an account-level
`User.facetPack` still wins when set. One account can therefore run several
scopes with different ontologies.

## [1.3.1] - 2026-08-05

### Fixed
- A single transient failure no longer makes an event invisible to search. Jobs
  were enqueued with no options, so BullMQ's default of one attempt applied: for
  `embed_event`, one rate limit or timeout left the event permanently absent from
  every vector query — stored, keyword-retrievable, and silently missing, with
  one log line to say so. Jobs now retry three times with exponential backoff,
  and `GET /metrics/digest/:scopeId` reports embedding coverage so a surviving
  gap can be found rather than guessed at.

### Docs
- The 2026-08-05 core audit ledger closes out its unaudited scope: retrieval,
  the assistant runtime, working memory, the event store and data GC, and
  pgvector recall quality. Two hypotheses in it were tested and rejected.

## [1.3.0] - 2026-08-05

### Added
- `GET /v1/facet-pack` exposes the tenant's active ontology: its facets, their
  capacity, whether conversation may overwrite them, whether they take facts only
  from documents, and which classifier types route into them. Read-only —
  swapping a pack stops displaying facts in facets the new pack does not define,
  which is not a button.

### Fixed
- Consolidation resolves contradictions in a protected facet instead of letting
  incompatible facts accumulate, keeping the document-sourced side and retiring
  the loser. It already ran on every digest touching a facet, so this costs no
  extra model call.
- A tenant's installed pack drives the classifier. A pack could declare
  `routesFrom: ["case_event"]` while nothing emitted `case_event`; the two
  extensibility mechanisms were connected in one direction only.
- Grounding evidence carries `eventSnippetsTotal`, so "here is why I said that"
  showing 5 of 30 says so.

## [1.2.0] - 2026-08-05

Two months of work, and the largest release since the freeze. It has two halves:
the memory-facts surface built through June and July, and an audit that came out
of investigating a LongMemEval comparison whose numbers turned out to be an
artifact. The audit found that several of the engine's stated guarantees did not
hold in the code, so that half is mostly repair. Only the audit half carried
changesets at the time; the package CHANGELOGs are correspondingly thinner than
this range.

### Added — the facts surface
- `GET /v1/memory/facts` returns grouped, forgotten-filtered memory facts, and
  `POST /v1/memory/facts/forget` suppresses a fact and soft-suppresses its
  evidence event (`ForgottenFact` table, `MemoryEvent.suppressedAt`). Suppressed
  events are excluded from retrieve, list and digest input, and forgotten facts
  are pruned from digest state before generation so a reworded forget cannot
  resurface.
- `POST /v1/memory/notes` writes a durable note through a deterministic writer,
  backed by a new `notes` facet and display group, so durable non-personal
  information has somewhere to live.
- `DELETE /v1/scopes/:id` cascade-deletes a scope and all its data.
- `GET /v1/memory/relationship-context/:scopeId` is served on the `/v1` path.
- Stage 2 extracts conversational profile facts into every displayable facet
  rather than `identity` alone, with stream authority for conversation-sourced
  facts, internal ids stripped from fact text, and the style facet broadened to
  cover working style.
- Facet consolidation runs on changed facets during digest — an LLM pass with
  validation and retry, fail-open, carrying the earliest `addedAt` forward.

### Fixed — auditability
- Fact history survives a digest. `normalizeDigestState` rebuilt the registry as
  `.filter(e => !e.supersededBy).slice(-100)` and ran on every digest, so each
  one deleted the supersession history it inherited: a chain existed only until
  the next run. Active facts are never dropped on load, and history is kept to a
  bounded most-recent 500.
- Capacity eviction and facet consolidation retire records instead of deleting
  them. Consolidation touches a facet on the common path, not a rare one.
- Every discard is recorded with a reason and persisted to
  `Digest.selectionLog`. Eight places could previously drop information with no
  trace.
- New: `GET /v1/memory/facts/:factId/provenance` returns a fact's evidence and
  its full version chain from any version in it;
  `GET /v1/memory/digests/:digestId/selection` returns what a digest kept and
  what it discarded.

### Fixed — drift
- Write protection applies on the path that runs every digest. It existed only on
  the classifier-driven path, so a 0.6-authority sentence from chat could
  supersede a 0.85-authority fact from an uploaded document.
- A document-authority facet with no document in the run no longer writes a fact
  the registry has no record of.
- The protected-fact contradiction check was dead: key tokens came from an
  ASCII-first ordering, so dates crowded out the terms identifying the fact and
  the check never fired. Protected facts are full of dates.
- `checkContradiction` sees write-protected profile facts, not just
  `stableFacts`, and drift metrics observe the fact registry, where user facts
  actually live.

### Changed — ontology
- The seven personal-life facets are no longer wired into the engine. They lived
  in eight places that could drift apart; they are now one replaceable pack, and
  the core stores, protects, supersedes and retrieves without knowing what a
  facet means. Facets declare their own stage-1 routing, display group, capacity,
  protection and document authority.
- Packs resolve per tenant from `User.facetPack`, not per process, so one
  deployment can serve customers with different ontologies.

### Changed — retention
- `pinned` on an ingested event means it must not lose a budget competition.
  Documents already outranked chat but competed with each other by recency, so
  the oldest — typically a durable one like a resume, uploaded once — was dropped
  first.
- Updated documents re-trigger the digest. The "anything new" check compared
  `createdAt`, which an upsert keeps, so re-uploading a corrected document changed
  the stored document and nothing else.
- Per-facet capacity is configurable via `DIGEST_FACET_CAPS`.

### Behaviour change worth knowing
Conversation can no longer add facts to a document-authority facet (`identity` in
the default pack) when the run has no document. Such facts were previously
written to the profile with no registry entry behind them — visible but
unciteable and impossible to supersede. Re-uploading the document remains the
supported path. Rejections appear in the selection log as `no_document_evidence`.

## [1.1.0] - 2026-06-22

Freeze-readiness release. The `/v1` API is now frozen — see STABILITY.md. This
release is additive + internal hardening only; the `/v1` contract is unchanged
since 1.0.0.

### Changed / Removed
- Trimmed the runtime to `apps/api` + `apps/worker` + `packages/*`. Removed the
  peripheral apps (demo-web, adapter-telegram, cli, adapter-mcp) and demo-only
  code paths.
- Removed the in-process rate limiter — rate limiting now belongs to the hosting
  gateway/reverse proxy (the open core no longer rate-limits in-process). `429`
  was never part of the `/v1` contract.

### Added
- Drift-control robustness: property-based (fast-check) + adversarial regression
  tests over the digest-control pure functions; deterministic `idFactory`/`nowFactory`.
- Multi-instance safety: `rebuild_digest_chain` now runs under the distributed
  digest-lock; the periodic maintenance tasks run as cluster-safe BullMQ repeatable
  jobs; the runtime recall caches are bounded (`BoundedTtlCache`).
- pgvector **HNSW index** on embeddings, with the vector query aligned to the
  cosine operator so the index is used at scale.
- Per-stage latency logs for retrieve and digest (`retrieveTimings`/`digestTimings`).
- Request body size limit (`MAX_REQUEST_BODY_BYTES`, default 1 MB) with clean
  413 (too large) / 400 (malformed JSON) responses.
- Daily data-lifecycle GC (`data_gc`): prunes old digest/snapshot history (always
  keeping the latest per scope), old job logs, and terminal reminders.
- `examples/quickstart.sh` — a runnable `/v1` worked example.
- `STABILITY.md` — the `/v1` freeze + stability policy.

### Fixed
- `consistencyCheck` no longer false-flags `goal_contradiction` when a summary
  appends prose after the goal.
- digest + state snapshot are now written atomically in a transaction.

## [1.0.0] - 2026-03-18

### Added
- Assistant runtime turn flow with policy profiles, overrides, structured evidence, and grounded answer evidence.
- Provider-neutral model configuration with role-specific chat, structured-output, and embedding endpoints.
- Configurable model timeout support via `MODEL_TIMEOUT_MS` for slower digest and benchmark workloads.
- Replay consistency analysis with transition taxonomy and confidence-aware state diffs.
- Working-note continuity benchmarking, including open-question and risk retention / intrusion metrics.

### Improved
- Protected-state evolution for goals, constraints, decisions, todos, questions, risks, and volatile context.
- Durable numbered decision and todo retention across digest selection, state merge, and drift evaluation.
- Long-term memory reliability scoring with replay stability, grounded response quality, and state-confidence signals.
- Benchmark, ablation, trend, and research-report outputs for working-note continuity and replay explainability.

### Docs
- Vision, drift, digest state, assistant runtime, evaluation, provider abstraction, and benchmarking docs now reflect the memory-first 1.0.0 positioning.
